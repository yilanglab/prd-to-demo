# 原型规划

## 从任务到页面

先写用户任务，再选择页面。每个 P0 任务必须包含：

1. 角色与触发场景。
2. 可发现的入口。
3. 必需输入和默认值。
4. 系统反馈与后台动作。
5. 成功结果和下一步。
6. 错误、无权限、重复操作和回退。
7. 可供演示验证的证据。

页面不是需求的同义词。同一任务可以跨多个页面，同一页面也可以承载多个任务。

## 信息架构

- 按用户工作目标组织一级导航，不按 PRD 章节照搬。
- 为跨阶段对象提供清晰的对象切换和上下文保持。
- 区分“创建新对象”的入口与“继续处理已有对象”的入口。
- 为角色不可操作但可查看的内容保留一致的信息入口。
- 避免直接暴露仅供设计推理使用的路径编号或内部术语。

## 状态矩阵

每个页面或关键模块至少检查：

| 状态 | 需要回答的问题 |
| --- | --- |
| 正常 | 当前对象、可用动作和下一步是否清楚？ |
| 空 | 为什么为空，用户现在能做什么？ |
| 加载 | 是否有进度语义和状态公告？ |
| 错误 | 发生了什么，能否重试或恢复？ |
| 成功 | 结果是否持久，下一步在哪里？ |
| 无权限 | 是隐藏、禁用还是只读，原因是否在必要时出现？ |

不适用的状态要记录理由，不能因 Demo 数据恰好不触发而省略。

## P0/P1/P2

- **P0**：演示核心价值所必需的端到端任务，缺失会使产品无法被理解。
- **P1**：显著增强可信度的异常、协作或次要任务。
- **P2**：配置、深层历史或可延后能力，不影响首条故事线闭环。

优先级描述任务价值，不描述开发难度。每个 P0 入口都必须有反馈，不允许用无响应按钮占位。

## Mock 数据计划

- 使用稳定 ID、真实字段和对象关系，不使用 `test1` 或无意义随机值。
- 覆盖主链路所需状态、至少一个空状态、一个错误或受限状态。
- 把异步后台动作表达为可切换状态或可预测时间线。
- 明确哪些数据由真实后端、权限服务或人工流程产生。
- Mock 只模拟结果，不伪造真实安全性、持久化或外部调用。

## 演示叙事

按“问题 → 角色任务 → 关键决策 → 系统反馈 → 业务结果 → 研发边界”组织。演示步骤要写可见操作和预期结果，不写抽象口号。

面向产品强调范围、状态与规则；面向研发强调对象、状态转换、Mock 边界、接口与风险。两种叙事使用同一事实合同。

## 原型计划门禁材料

提交给用户确认：IA、页面清单、P0 流程、状态矩阵、Mock 数据范围、组件计划草案和演示脚本。未确认前不初始化或修改产品前端。
