# 前端技术栈与组件决策

## 不可变组合

| 层 | 选择 | 职责 |
| --- | --- | --- |
| 应用 | React + TypeScript | 页面、状态和类型合同 |
| 组件源码 | shadcn/ui | 可拥有、可组合的项目内组件 |
| 行为 Primitive | `@base-ui/react` | 弹层、焦点、键盘与无障碍行为 |
| 样式 | Tailwind CSS | 布局与语义 Token 消费 |
| 图标 | `lucide-react` | 常规产品图标的唯一来源 |

新项目采用 shadcn 的 Base UI 路线 `base-nova`。已有项目先读取 `components.json`、依赖和现有组件；保留合法配置与用户代码，但新 Demo 页面必须使用 Base UI-backed 组件。若现有 shadcn 不在 Base UI 路线上，在 `DESIGN.md` 记录保留范围、隔离方式或迁移计划；不得为了统一模板而重置项目。

## 组件决策顺序

对每个新增控件依次执行：

1. 搜索现有 `components/ui` 及业务组件，先确认其是否 Base UI-backed：是则优先复用其公开 API；否则保留为既有页面的隔离依赖，不把它用于新 Demo 页面，并记录隔离或迁移计划。
2. 检查 shadcn registry；使用查询或 dry-run 了解文件和依赖后再安装。
3. 若 shadcn 无匹配组件，组合 Base UI Primitive，并保留其语义、焦点和键盘模型。
4. 仅当前三层无法表达产品行为时自研；记录缺口、API、状态与无障碍合同。

顺序不可跳过，因为自研交互组件最容易产生焦点、键盘、弹层定位和一致性缺陷。

## 禁止项

- 禁止用 `div + click` 重写 Button、Select、Menu、Dialog、Drawer、Tabs、Tooltip 或其他已有控件。
- 禁止用 Emoji、字符画或手绘 SVG 替代 Lucide 产品图标。
- 禁止在业务页面散落十六进制、RGB 或脱离 Token 的品牌颜色。
- 禁止创建无响应按钮、错误路由或只有视觉没有状态变化的控件。
- 禁止用占位文本掩盖未实现后台；要明确 Mock 边界和结果来源。
- 禁止因安装新组件覆盖已有 `components/ui` 修改。

## 设计基础

在 `DESIGN.md` 先定义再消费：

- 基础色谱与语义色彩映射。
- 字体家族、字阶、行高与字重。
- 间距、尺寸、圆角、描边与阴影谱系。
- 页面内容上限、网格、密度、断点和横向溢出策略。
- 默认、悬停、按压、聚焦、禁用、加载和错误状态。
- 动效用途、时长、缓动和 `prefers-reduced-motion` 行为。

业务组件只引用语义 Token。视觉方向可以随项目变化，但基础参数必须可追踪、可复用。

## 实现顺序

1. 建立应用壳、路由、Token 和共享 Primitive。
2. 建立类型化 Mock 数据与状态转换。
3. 纵向实现一条 P0 任务，验证对象上下文能跨页保持。
4. 补齐其正常、空、加载、错误和无权限状态。
5. 扩展其余 P0，再处理 P1/P2。
6. 每次新增组件后同步组件文档或设计系统展示（若项目已有）。

## 响应式与可访问性

- 在 375、768、常规桌面和 2560 像素级别核对内容策略，不只缩放桌面布局。
- 表单使用可访问名称；弹窗进入时聚焦合理元素，关闭后恢复触发器。
- 键盘可完成关键任务，焦点样式不依赖颜色差异过低的描边。
- Tooltip 不承载完成任务所必需的信息，触屏和键盘必须有等价路径。
- 表格在窄屏选择重排、隐藏次要列或局部滚动；禁止整页横向溢出。
