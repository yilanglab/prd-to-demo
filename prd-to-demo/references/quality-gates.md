# 门禁与验证

## 门禁 1：产品合同

通过条件：

- 产品目标、范围和非目标明确。
- 角色、对象、生命周期、规则与权限可追踪到来源。
- PRD 明确、推导、Mock 和待确认四类信息已分开。
- 冲突与高影响未知项已提交用户决策。
- 用户明确同意进入原型规划。
- 在用户明确确认产品合同前，输出不得包含页面清单、IA、P0/P1/P2、状态矩阵、Mock 计划或 Demo Script；即使用户在同一请求中要求产品分析和原型计划也不得例外。

未通过时只更新分析文档，不创建页面或初始化前端。

## 门禁 2：原型计划

通过条件：

- 已获得门禁 1 对产品合同的明确确认；未满足此前置条件不得生成 IA、页面清单、P0/P1/P2、状态矩阵、Mock 计划或 Demo Script 等门禁 2 材料。
- IA、页面清单和入口关系明确。
- P0 主任务从入口到结果闭环。
- 状态矩阵覆盖正常、空、加载、错误、成功和无权限，或记录不适用理由。
- Mock 数据边界、真实后台责任和演示叙事明确。
- 用户明确同意进入设计与研发。

未通过时不修改产品前端。

## 交付物校验

依次运行：

```bash
node scripts/validate-deliverables.mjs --target <项目目录> --stage product
node scripts/validate-deliverables.mjs --target <项目目录> --stage prototype
node scripts/validate-deliverables.mjs --target <项目目录> --stage all
```

校验脚本只检查结构和最低工程合同，不能代替人工验证产品语义。

## 自动化证据

实际运行项目定义的：

- `lint`
- `typecheck`
- `test`
- `build`
- diff check（Git 项目使用 `git diff --check`）

记录命令、退出码和关键结果。若脚本缺失、环境阻塞或未执行，标为“未验证”；不要用源码存在或历史结果冒充本轮通过。

## 浏览器 Smoke

至少覆盖：

1. 首页与一级导航。
2. P0 主任务全链路。
3. Dialog、Drawer、Menu、Select 等关键弹层。
4. 正常、空、加载、错误和无权限状态。
5. 对象切换、返回和刷新后的上下文。
6. 控制台运行时错误和失败网络请求。

本地服务必须使用项目固定端口和健康 URL。监听端口不等于服务正确，需核对工作目录、命令和实际页面。

## 响应式与无障碍

- 检查移动 375×812、平板 768×1024、常规桌面和宽屏 2560×1440。
- 检查整页横向溢出、内容上限、固定元素遮挡和触控目标。
- 用键盘执行 P0 任务；检查焦点可见、弹窗焦点进入与恢复。
- 检查表单、图标按钮、组合框和状态公告的可访问名称。
- 检查减少动效设置下仍能理解状态变化。

若工具无法改变真实 CSS 视口，区分环境限制与产品缺陷，并把无法核实项标为未验证。

## 交付报告

报告以下事实：

- 已完成的 P0/P1/P2 范围。
- PRD 追踪覆盖率与未覆盖需求。
- 自动化与浏览器验证结果。
- Mock 数据、模拟后台动作和真实研发接口建议。
- 未验证项、已知缺口和风险。
- 用户确认记录与范围变更。

只有实际验证通过的项目才能写“通过”。
